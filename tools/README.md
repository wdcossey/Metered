# tools/

Developer tooling. Nothing here ships in a package. The tools that load `baseui` (`tokens/`, `reference/`) need `npm install` at the repository root
(Base Web's `baseui`, pinned, with React and Styletron, which its styled components load).

| Tool | What it does |
|---|---|
| `tokens/gen.js` | Writes `src/Metered.Themes/Tokens/*.g.axaml` from `baseui`'s LightTheme and DarkTheme (colours, sizing, borders, lighting, animation, typography, the Button's box-shadows from `tokens/button-shadows.js`, the Slider's thumb shadow from `tokens/slider.js`), the part themes `Controls/{Button,Checkbox,FormControl,Input,Popover,ProgressBar,Radio,Slider,Spinner,Switch,Textarea}.Parts.g.axaml` (`tokens/button.js`, `checkbox.js`, `form-control.js`, `input.js`, `popover.js`, `progress-bar.js`, `radio.js`, `slider.js`, `spinner.js`, `switch.js`, `textarea.js`), and `Theming/ThemeDerivation.g.cs` (`tokens/theme.js`). `--check` fails if a file would change. |
| `tokens/theme.js` | What Base Web's `createTheme` and `createDarkTheme` derive, read by calling them (and the Button's style function) on sentinel values: which colours follow which foundation colour, what each Button shadow is made of, which paths are one object. Tables of names for `Metered.Themes.Theme` (ADR 0002). Run by `gen.js`. |
| `tokens/checkbox.js` | The Checkbox's part themes (`Controls/Checkbox.Parts.g.axaml`), from checkbox-v2's style functions, by `radio.js`'s writer as the fewest layered styles. Run by `gen.js`. |
| `tokens/radio.js` | The Radio's part themes (`Controls/Radio.Parts.g.axaml`), from radio-v2's style functions evaluated on a theme whose colours are their names, checked for every combination of states. Also the v2 controls' shared theme writer (with its `layered` mode) and conversions, which every other part-theme generator uses (`checkbox.js`, `form-control.js`, `input.js`, `popover.js`, `progress-bar.js`, `slider.js`, `spinner.js`, `switch.js`, `textarea.js`). Run by `gen.js`. |
| `tokens/slider.js` | The Slider's part themes (`Controls/Slider.Parts.g.axaml`), from Base Web's slider's style functions, by `radio.js`'s writer as the fewest layered styles; react-range's inline thumb cursor; and the thumb's literal shadow as a token (`Tokens/SliderBoxShadows.g.axaml`). Run by `gen.js`. |
| `tokens/input.js` | The Input's part themes (`Controls/Input.Parts.g.axaml`), from Base Web's input's style functions, by `radio.js`'s writer as the fewest layered styles; the icons' sizes from Base Web's Input rendered and their paths from its icons rendered (`delete-alt`, `show`, `hide`). Its `parts` and `themes` serve Textarea's; its `declare`, `padding` and `INHERITED` serve FormControl's. Run by `gen.js`. |
| `tokens/textarea.js` | The Textarea's part themes (`Controls/Textarea.Parts.g.axaml`), from Base Web's textarea's styled components (`StyledTextAreaRoot`, `StyledTextareaContainer`, `StyledTextarea`) and BaseInput's clear icon, with `input.js`'s parts and themes for the textarea's states. Run by `gen.js`. |
| `tokens/form-control.js` | The FormControl's part themes (`Controls/FormControl.Parts.g.axaml`), from Base Web's form control's style functions (`CaptionMessage` a style object), by `radio.js`'s writer as the fewest layered styles; the caption's two icons (`alert`, `check`) at the size Base Web's FormControl renders them. Run by `gen.js`. |
| `tokens/popover.js` | The Popover's part themes (`Controls/Popover.Parts.g.axaml`), from Base Web's popover's style functions evaluated with its colours, radii and shadows as their token names, by `radio.js`'s writer as the fewest layered styles; the body's entrance (0.1 s while `:is-open:is-animating`), a hover popover's first 0.1 s of not taking the pointer (`IsHitTestVisible`), and `Popover.StyledPadding`. Run by `gen.js`. |
| `tokens/spinner.js` | The Spinner's part theme (`Controls/Spinner.Parts.g.axaml`), from Base Web's spinner's style function on a theme whose colours are their names: a state style for each size, sizing token, length and dropped value of `$size` and `$borderWidth`, and the turn, unless `:metered-still`. Run by `gen.js`. |
| `tokens/switch.js` | The Switch's part themes (`Controls/Switch.Parts.g.axaml`), from Base Web's switch's style functions, by `radio.js`'s writer. Run by `gen.js`. |
| `tokens/progress-bar.js` | The ProgressBar's part themes (`Controls/ProgressBar.Parts.g.axaml`), from Base Web's progress bar's style functions, by `radio.js`'s layered writer, with its motion (the fill's transition, the endless animations, off while `:metered-still`). Run by `gen.js`. |
| `reference/oracle.js` | Calls a Base Web styled component's own style function with a theme and `$` props, and resolves the result for an interaction state by the cascade `precedence.js` measured. |
| `reference/cases.js` | Writes `tests/Metered.Tests/Reference/*.oracle.json`: the oracle's answer for every case the tests build. `--check` as above. |
| `reference/themes.js` | For `cases.js`: `theme.oracle.json`, Base Web's own `createTheme` and `createDarkTheme` on eight sets of foundation colours and overrides, every token in Metered's keys. |
| `reference/checkbox.js` | For `cases.js`: `checkbox.oracle.json`, checkbox-v2's oracle. |
| `reference/radio.js` | For `cases.js`: `radio.oracle.json`, radio-v2's oracle, computed apart from the generator. |
| `reference/slider.js` | For `cases.js`: `slider.oracle.json`, the slider's oracle, react-range's own `normalizeValue` (loaded from `baseui`'s place in `node_modules`) on the values a drag or a key gives, and JavaScript's `String(n)`. |
| `reference/input.js` | For `cases.js`: `input.oracle.json`, the input's oracle: Base Web's own Input rendered (react-dom/server) with every part recorded, each part's style function run with the props it was given, on the light and dark themes; the icons' paths. Its `markup`, `declarations`, `sides`, `colour` and `icon` serve `reference/form-control.js`, and `markup` `tokens/form-control.js`. |
| `reference/textarea.js` | For `cases.js`: `textarea.oracle.json`, the textarea's oracle: Base Web's own Textarea rendered (react-dom/server) with every part recorded, each part's style function run with the props it was given, on the light and dark themes. |
| `reference/form-control.js` | For `cases.js`: `form-control.oracle.json`, the form control's oracle: Base Web's own FormControl rendered (react-dom/server) with every part recorded, round a child that records what `cloneElement` gives it with the defaultProps of Input, Textarea, Checkbox or RadioGroup; each part's style function run with the props it was given, on the light and dark themes; and the block flow's positions from its margins and lines. |
| `reference/popover.js` | For `cases.js`: `popover.oracle.json`, the popover's oracle: each part's colours on the light and dark themes; the body's margin, entrance start and motion and the arrow's position by placement (its style functions checked against utils.js's helpers); its constants, default props and `StyledPadding`; and popper.js's placements, first and next update, from `tether.g.json`. |
| `reference/spinner.js` | For `cases.js`: `spinner.oracle.json`, the spinner's oracle. |
| `reference/switch.js` | For `cases.js`: `switch.oracle.json`, the switch's oracle. |
| `reference/progress-bar.js` | For `cases.js`: `progress-bar.oracle.json`, the progress bar's oracle: Base Web's own `ProgressBar` rendered (react-dom's server renderer) with every part overridden by a recorder, each part's style function evaluated with the props it was given. |
| `reference/css.js` | CSS values (colours, lengths, box-shadows, weights, families) to Avalonia's. Throws on a format it doesn't know. |
| `breakage/run.js` | Breaks each behaviour in a list on its own, in a fresh clone, and checks that a test goes red ([`docs/performance/README.md`](../docs/performance/README.md#breakage-runs)). Needs git, Node and the .NET SDK, not `npm install`. From Cornflower and Avonic. On a timeout it kills what the run left running from the clone (`breakage/strays.js`): on Linux and macOS, never `run.js` or its ancestors, with the path matched literally and whole; `node tools/breakage/strays.test.js` tests it on real processes, and CI runs it on Linux. On Windows it spares only `run.js` and matches the path as a wildcard prefix (#24). |
| `reference/fonts.js` | Measures Uber Move on baseweb.design against OFL candidates for its substitute, in one headless Chromium: widths, glyph heights, line metrics, the baseline in the ramp's line boxes ([`docs/decisions/0003-font.md`](../docs/decisions/0003-font.md)). Prints Markdown; `--write` writes `reference/fonts.g.json` (generated: don't hand-edit). Network and a Chromium, as below. Uber Move is only rendered, never saved. |
| `reference/tether.js` | Runs popper.js 1.16.1 (`node_modules/popper.js`) in headless Chromium on plain boxes with Base Web's `TetherBehavior` and `Popover` options, its first update and its next with the margin at the placement chosen; `--write` writes `tether.g.json` (generated: never hand-edit it), which `reference/popover.js` reads. Without `--write` it prints a summary. Run by hand: CI's `cases.js --check` reads `tether.g.json` but never re-runs popper.js, so run it again after any change to baseui or popper.js. Needs a Chromium for `playwright-core` (`npx playwright-core install chromium`), not the network. |
| `reference/precedence.js` | Reads computed styles on baseweb.design in headless Chromium (Playwright): which of `:hover`, `:active` and `:focus-visible` wins. Needs a Chromium for `playwright-core` (`npx playwright-core install chromium`). |
| `android/run.ps1` | The device run (PowerShell 7.4): builds the Android head, installs it on the one phone `adb devices` lists (or, with several, the one `ANDROID_SERIAL` names), opens each `-Page` cold and `-Reopen` times warm, and writes each open's ready line (and, with `-Configuration Debug`, its cost line) to the page's `run.json`, with `logcat.txt`, a frame after the cold start, and `summary.json` for the run. `-SelfTest` checks its parsers on `android/fixtures/` with no adb; CI runs it. Needs the .NET SDK's `android` workload and an Android SDK with adb. Anything on a phone is ask-first (PROCESS §2) and goes through the device lease. First run on a Pixel 8 on 2026-11-17 (#29). See [`android/README.md`](android/README.md). |
| `real-window/drive.ps1` | The real-window run (Windows; pwsh 7 or Windows PowerShell 5.1): builds the desktop sample, opens its real window and drives it with real mouse, keys and injected touch: every page from the list and back, the phone's view under the bar, Alt+Left, Light/Dark, resizing, and a section per control with input of its own. Saves a frame per page and exits 1 on a failed check; `-Only` runs some sections. It takes over the desktop: ask-first (PROCESS §2), through the device lease. `real-window/selftest.ps1` checks its helpers and the script as parsed, with no window, on any OS; CI runs it. From Cornflower's. See [`real-window/README.md`](real-window/README.md). |
